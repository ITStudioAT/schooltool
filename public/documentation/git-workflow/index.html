Ein Feature ohne Übernahme verwerfen

Mit gitdiscard schließt du ein nicht mehr benötigtes Feature. Seine Änderungen werden nicht in main übernommen. Live-Anwendung, Vorschau-Daten und lokale Datenbanken werden nicht verändert.

Vorbereitung​

Alle beteiligten PCs benötigen die aktualisierten Git-Helfer. Im Projektordner einmal composer setup:powershell ausführen und ein neues Terminal öffnen. Für das aktuelle Terminal genügt . ./scripts/git_helpers.ps1.

Sichere ungesicherte Arbeit zuerst. Der Befehl verlangt einen sauberen, mit GitHub übereinstimmenden main. Ist das Feature in einem anderen Arbeitsverzeichnis ausgecheckt, dort zuerst den Status und laufende Arbeit prüfen. Ein sauberer Hilfs-Worktree kann mit git -C "EXAKTER-PFAD" switch --detach HEAD am gleichen Commit bleiben und den Branch freigeben; seine Dateien werden dabei nicht entfernt.

Das letzte aktive Feature ablösen​

Für eine Vorschau des gespeicherten Hauptstands gibt es gitpreview -Main. Es wird kein Ersatz-Feature angelegt. Die Live-Anwendung und GitHub-main werden nicht verändert.

Beim ersten Umstieg nutzt die Vorplanung die bereits vorhandenen Status-, Export- und Planprüfungen. Die neue Abschlussfunktion wird im geprüften Vorschaupaket mitgeliefert und erst nach dessen Installation aufgerufen. Dafür muss die Live-Anwendung nicht eigens aktualisiert werden. Fehlen bereits die bisherigen Snapshot-Befehle oder die Vorschau-Isolation, muss zuerst die dokumentierte Ersteinrichtung erfolgen; die Planung stoppt dann vor Veröffentlichung.

Wenn die neue Funktion noch als lokale Änderungen vorliegt, zuerst alle Änderungen prüfen und normal mit gitsave "Main-Vorschau unterstützen" speichern. Danach im Hauptprojekt auf sauberem, aktuellem main:

. ./scripts/git_helpers.ps1
gitpreview -Main

Beim Wechsel von Matura oder einem anderen Feature verlangt der Dialog zunächst REFRESH, danach PREVIEW. Die bisherigen aktiven Testdaten der Vorschau werden nach privater Sicherung durch eine frische Live-Kopie ersetzt. Es werden keine separaten Teststände je Feature aufgehoben. Nur die isolierte Vorschau erhält den geprüften Code und dessen Migrationen.

Erst nach erfolgreichem Abschluss fortfahren:

gitdiscard "feature/matura"

Im Dialog DISCARD feature/matura bestätigen. Der Name muss dem tatsächlich gewünschten Feature entsprechen. Der Main-Vorschaumodus benötigt keine Feature-Reservierung; es bleibt kein künstlicher Ersatzbranch zurück.

Optional: gitpreview prepare -Main bereitet nur lokal vor; gitpreview resume <Bundle-ID> -Main setzt diesen Kandidaten vor Veröffentlichung fort. -Main lässt sich nicht mit -Feature kombinieren. Eine spätere Aktualisierung im Main-Modus behält normalerweise die Vorschau-Testdaten; gitpreview -Main -RefreshData ersetzt sie ausdrücklich. Auch der spätere Wechsel von Main zu einem Feature verlangt beim Datenersatz REFRESH und PREVIEW.

Bei Transfer-, Import-, Migrations- oder Abschlussfehlern bleibt der Verwerfen-Schutz bestehen. Die private Wiederherstellungssicherung und der angefangene Kandidat sind zu prüfen; nicht automatisch erneut starten oder Marker entfernen. Geänderte Main-Commits, Vorschaupläne oder belegte Operationssperren führen ebenfalls zum sicheren Abbruch. Die Vorschau muss den vollständigen Abschluss bestätigen, bevor das alte Feature geschlossen werden darf.

Befehl ausführen​

Das folgende Beispiel verwendet ein Feature namens testfunktion:

gitmain
gitdiscard "testfunktion"

gitdiscard "feature/testfunktion" ist gleichwertig. Prüfe den angezeigten Namen und Commit. Bestätige nur das tatsächlich nicht mehr benötigte Feature mit:

DISCARD feature/testfunktion

Jede andere Eingabe bricht ab. main erhält keinen Merge. Der exakt geprüfte Feature-Branch und seine zugehörige Reservierung werden auf GitHub gemeinsam entfernt. Danach wird der entsprechende lokale Branch gelöscht, sofern er weiterhin unverändert und in keinem Worktree ausgecheckt ist. Andere Features bleiben offen.

Wann der Befehl stoppt​

  • Ungesicherte Änderungen oder ein nicht aktueller main.
  • Abweichende lokale und entfernte Feature-Commits, beispielsweise noch nicht gespeicherte Commits.
  • Fehlende, widersprüchliche oder inzwischen veränderte Feature-Reservierung.
  • Ein Worktree verwendet noch den Feature-Branch.
  • Das Feature ist in der gemeinsamen Vorschau aktiv oder deren Zustand lässt sich nicht sicher prüfen. Die vorhandene PREVIEW-SSH-Konfiguration und eine erreichbare Vorschau sind erforderlich.
  • Ein anderer Vorgang veröffentlicht gerade die Vorschau dieses Features oder verwirft es. Alle beteiligten PCs müssen die neuen Helfer verwenden.

Der Befehl erzwingt keine dieser Aktionen. Er führt keine Migrationen aus, setzt keine Datenbank zurück und entfernt keine Vorschau-Dateien, Kandidaten oder alten Prüfnachweise. Alte Nachweise erlauben keine Veröffentlichung eines bereits geschlossenen Features.

Wiederherstellung und unterbrochene Vorgänge​

Vor dem Entfernen legt der Befehl lokale Wiederherstellungsreferenzen an und zeigt sie an:

refs/schooltool/discarded/<Lifecycle-ID>/<Vorgangs-ID>/feature
refs/schooltool/discarded/<Lifecycle-ID>/<Vorgangs-ID>/reservation

Damit bleiben der ursprüngliche Feature-Commit und seine Reservierung erhalten. Diese Sicherung gehört zu diesem lokalen Repository; sie wird nicht als weiterer Feature-Branch veröffentlicht.

Meldet die Ausgabe, dass GitHub bereits bereinigt wurde, die lokale Bereinigung aber gestoppt hat, ist der verbliebene lokale Branch absichtlich geschützt. Nicht blind erneut löschen. Auch eine nach einem Verbindungsabbruch verbliebene Sperre unter codex/operations/<Lifecycle-ID> erst nach Prüfung des genauen Vorgangs freigeben. Der Befehl überschreibt weder eine fremde Sperre noch zwischenzeitliche Arbeit.

Unterschied zur Freigabe​

gitrelease übernimmt ein fertiges Feature in main. gitdiscard schließt ein verworfenes Feature ohne diese Übernahme. Keiner dieser Befehle startet automatisch ein Live-Deployment.
